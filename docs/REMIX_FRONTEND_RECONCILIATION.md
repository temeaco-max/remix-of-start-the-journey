## Deferred — duplicate information architecture (not imported)

`routes/audit.tsx`, `routes/cards.tsx`, `routes/credentials.tsx`, `routes/secure-execution.tsx`.

Canonical already implements these surfaces as one page: `src/routes/trust.tsx` consuming
`src/lib/trust-api.ts` (`fetchTrustOverview`, `freezeTrustCard`, `cancelTrustCard`,
`stopExecutionSession`, `exportTrustAudit`; types `Credential`, `VirtualCard`,
`AuditEntry`, `ExecutionSession`, `ExecutionAction`).

Importing the four routes would duplicate routes and split the trust IA, contrary to
"no duplicate routes". They are not missing content; they are an alternative (four-page)
presentation with additional write affordances.

Backend contracts for those write affordances **do** exist in the canonical backend
(`src/routes/secureServicesRoutes.ts`, mounted at `/api/v1`):
`POST /cards`, `POST /cards/:id/freeze`, `DELETE /cards/:id`, `GET|POST /protections`,
`POST /credentials`, `DELETE /credentials/:id`, `POST /execution/sessions`,
`POST|GET /execution/sessions/:id/actions`, `GET /audit?limit`, `GET /audit/export`.

Smallest safe resolution if the write affordances are wanted:
add the missing functions to canonical `src/lib/trust-api.ts` and expose them in
`trust.tsx` — **not** by importing the four routes. Requires a product decision on the
trust IA; deferred.
